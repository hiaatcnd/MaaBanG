## MaaBanG v0.6.24

新增竞演演出，并改进触控恢复、开演准备和运行环境一致性。

### 新功能与修复

- **竞演演出**：在“Maa代打演出 → 演出模式”中选择竞演，支持普通／特别类别、活动歌曲／自由选歌房间。自由房间使用独立的歌曲配置，可指定歌曲或不指定歌曲；开演前仍按房间实际歌曲、难度和火数预览确认。新模式追加在列表末尾，保留原有模式顺序。
- **联网结算**：遇到首次每日演出报酬选择时明确提示，避免重复点击未启用的确认按钮；结算后回到房间选择页即结束本轮，避免误点“确定”再次匹配。
- **演出画面**：统一识别准备页的 MV／3D 背景和 3D Cut in，包含 3D 模式下控件位置变化。指定谱面直接演出也会在开演前关闭这些效果，其他设置仍沿用当前页面，输入完成即结束。
- **触控与恢复**：统一使用 MaaFramework／Toolkit／Python 包 5.12.3，复用官方设备发现及增强触控能力。卡顿恢复可使用本次卡顿期间的新鲜截图，拒绝过期或旧相位证据；输入失败时不切换后端、不重放状态不明的操作。分别记录触控提交和等待耗时，清理失败时仍保存原始错误。
- **发布与曲库**：按校验和缓存依赖，清理旧原生库和插件，核对 Python 与界面使用的运行库；刷新中国服选歌目录及全服识别目录。

### 验证范围

- 发布前本地 689 项自动化测试、资源和 JSON Schema 检查通过。覆盖竞演房间、独立选歌、最终消耗确认、结算计次，以及触控失败、停止、恢复时效和运行库一致性。
- 测试账号在 MuMu 上完成普通自由选歌、特别活动歌曲房间两次 0 火完整竞演流程，均确认结算并返回主页；未使用饮料或星石。普通活动房间首次受每日奖励选择框阻断，人工选择后单独完成结算，不计为首次整轮成功。
- 触控卡顿改善另有录制数据回放证据；这不能证明卡顿根因已消除。本次未人为触发竞演断线或超时，相关行为以自动化回归为依据。
- 实机验证使用发布前的相同演奏代码；正式发布包另行验证完整性、源码一致性、运行库与 Agent 启动。

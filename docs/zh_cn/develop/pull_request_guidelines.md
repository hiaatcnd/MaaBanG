# PR 规范

向 MaaBanG 的 main 分支提交 PR，检查通过后合并。

- 说明具体问题、修改后的行为与验证结果。
- 验证结果写明命令、版本、通过／失败／跳过数量及原因，区分单测、截图回放、包／UI 检查和实机游戏结果；注明人工接管和未覆盖范围，详见 [Agent 验证约定](agent.md#日常验证与交付)。
- 游戏流程变更需要覆盖正常路径、页面异常、用户停止和资源不足。
- 涉及消耗的测试须获得测试账号所有者授权；不默认批量消耗道具。
- 不提交本地配置、原始 debug 截图、日志、缓存、解释器或发布 ZIP。
- 更新用户可见行为时同步 README 或任务说明。
- 新增自定义动作时同步入口注册、pipeline、界面配置与源码／包内自检清单，按变更补充测试和文档。
- 正式发布标签应指向已合并且检查通过的提交。

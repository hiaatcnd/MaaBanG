# Issue #20 修复与验证

日期：2026-10-05。对应 [Issue #20](https://github.com/hiaatcnd/MaaBanG/issues/20)。以下记录 v0.6.6 改动的源码验证；正式安装包以 Release 附件和 CI 检查结果为准。

## 问题与修改

1. **未 FULL COMBO 误选成分数 SS**：附件日志中，OCR 返回未 FULL 的框 `[731,319,76,21]`，随后点击 `(711,329)`；失败截图中面板位置已改变，未 FULL 圆点约在 y=271，SS 圆点约在 y=318 且选中。证据支持截图定位与实际点击之间坐标失效，滚动未稳定是当前主要判断；没有逐帧证据区分惯性滚动、截图时效等具体因素，不能据此认定 1280×720 本身是根因。该次任务实际报“未确认未 FULL COMBO 筛选”并停止，未把 SS 当成功；旧逻辑只检查旧坐标颜色，仍存在误判风险。`MiningLiveFlow` 现在等待面板稳定，OCR 后再次检查画面；发生位移时丢弃坐标。点击后重新定位未 FULL COMBO 并核验它自己的选中状态。等待和点击次数均有上限。
2. **开演前启动失败**：原 `chart_worker.py` 虽然通过 MaaFramework 截图，但自行调用 MuMuManager 匹配实例，并默认指定安卓 15 的 DLL。现在共用 `playback_controller.controller_config`，完整复用当前连接的配置和 ADB 地址；仅在缺少增强配置时使用框架发现设备，并要求地址唯一匹配。演奏继续使用框架 `EmulatorExtras` 和 `Maatouch`，观察控制器使用独立队列。增强未启用或连接失败时给出明确错误，不猜测另一台模拟器。主流程同时显示 worker 的实际准备失败原因。

开发探针 `tools/run_chart_probe.py` 同步取消 MuMu 路径、DLL、实例编号参数，改用可选的框架连接配置 JSON 或精确地址发现。用户说明及界面文案改为要求截图增强、多点触控和 16:9 横屏。

- 检查时工作区有 149 个已跟踪 PNG 缺失，其中资源目录 147 个。原文件状态保持不变；在 `debug/issue20/validation-assets` 独立复制当前资源，并仅从 HEAD 为该副本补齐缺失图片，资源检查通过。实机验证使用这个资源副本和当前 Agent 源码。因此不将原工作区描述为资源完整。

## MuMu 绑定审计范围

扫描了 Git 跟踪文件、固定版本 MFAAvalonia 源码和本地调试脚本。自有生产代码与开发探针中的 MuMuManager、`nx_main`、`nx_device/15.0`、`external_renderer_ipc.dll` 强绑定已移除。剩余相关内容如下：

- `run_costume_task.py`、`run_daily_task.py`、`run_live_presets.py`、`run_mining.py`、`run_live_task.py` 的默认 ADB 地址为 `127.0.0.1:16416`，均可用 `--address` 覆盖；这是开发默认值，不是模拟器类型限制。
- README 连接示例、历史验证记录、问题模板及测试中的 MuMu 启动器样例仍保留，分别用于说明历史环境、收集增强状态或测试前台应用识别。
- 固定版本 MFAAvalonia 的 `EmulatorHelper.cs` 有 MuMu 专用关闭分支，`MultiInstanceEditorDialogViewModel.cs` 默认选择 MuMu；上游同时提供其他类型选择，未将这些正常的厂商适配分支改成通用关闭命令。
- `debug`、旧安装包和历史发布目录中的旧实现是留存证据，未批量改写。二进制依赖未进行源码级审计。

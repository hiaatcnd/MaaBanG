# 谱面演出：首键同步与零抖动基线

> 本文保留 EASY 阶段的历史结果与当时限制。后续最高实际等级、完整手势与随机抖动的进展见 [最高等级谱面验证](chart_live_level30.md)；当前工具已扩展为清单中指定曲目的探针。

日期：2026-09-19。接续 [可行性研究](chart_live_feasibility.md)。本阶段限定 MuMu Android 15、MaaFramework 5.12.2、1280×720 框架截图，以及 SAVIOR OF SONG / EASY（Bestdori ID 306）。

## 实现与结果

解决了上一阶段的两个实际问题：

1. 显式配置 MuMu 安装目录、Android 15 的 `external_renderer_ipc.dll`、实例 1 和游戏包名 `com.bilibili.star.bili`。专用截图返回正常游戏画面，30 帧初测中位耗时约 13.5 ms，相比之前普通截图约 266 ms 大幅缩短。随后再次测量约 12.0 ms；这不是所有设备的性能保证。
2. 原型的“洋红色”首键条件在已保存截图上匹配数为零。改为轨道投影范围内的青色音符检测，跟踪至少 5 个向下移动点，使用最近最多 9 点估计到达判定线的时间。当前拟合时间与 `log(y)` 的关系；拒绝静止特征、过大的残差、过远预测以及跨长时间空档的轨迹。

`agent/chart_timing.py` 将 BPM 分段积分并编译 Single / 静止 Long 的 down/up 事件。触点按手势生命周期分配，同时长按与单键使用不同触点。`agent/chart_sync.py` 实现当前布局的检测与首键拟合。`tools/run_chart_probe.py` 提供显式授权参数的实验入口，开曲前核验歌曲、EASY、游戏自动关闭，并把火数设为 0 后重复检查消耗预览。

输入执行使用绝对单调时钟时间表；曲中不在同一个控制器队列插入截图。到期发送原子 down/up，异常或 Ctrl+C 时释放触点并尝试暂停。工具退出码 0 仅表示输入完成，不代表判定成功，必须读取游戏结算。

第一轮实机结果：**133 PERFECT，GREAT / GOOD / BAD / MISS 均为 0，最大连击 133，ALL PERFECT，得分 1,686,762**。238 个输入事件全部成功，调度迟到 P95 约 0.54 ms、最大约 4.71 ms。首键拟合残差约 1.03 ms；拟合残差和 SDK 返回耗时均不是游戏端绝对判定误差。

复现过程中保留了两次失败记录：`sync3` 因更大的图像处理范围降低采样率，旧二次拟合没有通过首键条件，随后错误锁定同轨后续音符，演出失败；`sync4` 的保护条件把准备页白色背景当成舞台，未发送谱面输入。修复包括缓存并裁剪检测区域、使用经两轮真实轨迹回放验证的对数拟合、首键丢失后禁止再次锁定、掉血后拒绝建立起点、限定舞台出现后的观察窗口，以及检查判定线青色边缘来排除白色加载页。失败记录不计入成功样本。

**最终代码的实机验证 `sync5`：84 PERFECT、49 GREAT、0 GOOD/BAD/MISS，最大连击 133，FULL COMBO，得分 1,312,820。** 使用 0 火、内置自动关闭、零抖动、`offset-ms=0`，238 个输入事件完成，调度迟到 P95 0.53 ms、最大 0.71 ms，视觉拟合残差 2.73 ms。结算证据为 `debug/chart_research/sync5/judgment.png`。当前最终实现仅有这一轮完整实机验证；不能把较早原型的一次 ALL PERFECT 当成最终实现已稳定达到同等精度。下一步应校准固定时间偏移，并扩大重复样本，之后才加入随机抖动。

结果摘要见 `docs/data/chart_sync_baseline_2026-09-19.json`。原始截图与事件记录在本地 `debug/chart_research/sync2/`；`judgment.png` 为人工核对的完整判定截图。样本仅覆盖此曲，不能推断 HARD/EXPERT 或任意设置已经可用。

## 复现

实验不会出现在正式任务列表，不会改动清火任务。先让游戏进入 **SAVIOR OF SONG / EASY 的准备页**，关闭内置自动。可用现有选歌工具的 `--prepare-only --song 306 --difficulty easy --fire 0`；未知弹窗需要先处理。

从 [Bestdori](https://bestdori.com/api/charts/306/easy.json) 获取原始 JSON 文件；必要时使用普通 User-Agent 与模拟器页 Referer。当前探针固定接受研究样本 SHA-256 `91294eebc4f51a1a7d596c2cf47388d12b2e8788080b81e1fda14880f3aa2a69`。哈希不符会拒绝开演，应先审查谱面变化，不能直接绕过验证。

在仓库根目录运行，路径和实例编号必须对应同一个模拟器；工具会通过 MuMuManager 对照实例与 ADB 地址。输出目录必须尚不存在。

```powershell
uv run --project agent python -X utf8 tools/run_chart_probe.py `
  --adb "C:/Program Files/Netease/MuMu/nx_main/adb.exe" `
  --address "127.0.0.1:16416" `
  --mumu-path "C:/Program Files/Netease/MuMu" `
  --mumu-lib "C:/Program Files/Netease/MuMu/nx_device/15.0/shell/sdk/external_renderer_ipc.dll" `
  --mumu-index 1 `
  --chart "debug/chart_research/306_easy.json" `
  --output "debug/chart_research/new-baseline" `
  --execute-zero-fire
```

`--offset-ms` 默认 0，只用于受控的整体偏移校准，限制在 ±100 ms。工具没有随机抖动开关：本阶段必须建立可重复的零抖动基线。谱面输入结束后会保存舞台/结果截图；奖励弹窗可能遮住最终判定，需要在现场查看并保存，不能由 SS 分数等级推断 ALL PERFECT。

## 当前限制

- 首键拟合是当前布局上的经验方法，对数拟合没有严格的物理误差保证。帧重复、掉帧、颜色和判定线改变都可能影响它；开局锁定失败会停止，不会盲播。
- 快速截图 API 请求耗时不等于真实帧龄，没有单独标定模拟器渲染到截图、以及触控到判定的端到端延迟。
- 不支持 Slide、Flick、移动长条、隐藏连接点、三指谱型；离线编译遇到这些会拒绝执行。不能将 EXPERT 谱面送入本探针。
- 曲中没有漂移修正或自动识别暂停/切后台。测试时保持游戏前台运行、布局和速度不变，不手动暂停；需要停止时中断探针。
- 当前坐标与视觉阈值绑定 1280×720 的已测舞台，不支持镜像、其他判定线位置或主题的自动校准。
- 没有加入随机抖动，也没有集成正式 UI。后续先测更多低难度谱与不同启动条件，再扩展滑条/滑键，最后做有界抖动对照。

## 正式功能的速度策略

用户已明确授权：**自动演出可以主动调整游戏下落速度，不仅限于测试时**。后续正式功能应把自动打歌速度作为独立配置，不要求维持用户手打时的高速设置。

开演前读取并记录速度；若当前设置无法提供足够的有效观测帧，则降低速度、读取界面确认设置生效，再重新建立同步。按谱面的 beat/BPM 执行时间不随视觉下落速度缩放；变化的是音符可见时间和视觉轨迹模型。不能只降速后继续复用旧的视觉外推参数，也不能在曲中突然改速。

当前已实现的探针尚未自动调整速度，本轮先验证原有速度下的同步。正式接入时应实现设置读回、校准参数与速度绑定、识别不足时的有界降速重试；不默认要求每局结束恢复手打速度，恢复可作为用户选项。

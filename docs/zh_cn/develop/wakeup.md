# 开始唤醒

“开始唤醒”是独立任务，默认不勾选。勾选后会先于本队列其他任务执行。一个队列只允许一个唤醒任务，不支持在同一队列中切换不同设备或账号。失败会终止队列，即使界面开启了“任务出错后继续”。

## 配置

| 选项 | 用途 |
| --- | --- |
| MuMu（mumu-cli） | 用 `mumu-cli.exe info/control` 查询并启动指定实例。适用于带该 CLI 的新版 MuMu |
| 自定义模拟器 | 指定启动 EXE 和参数；旧版 MuMu、雷电、蓝叠等可使用此模式，尚未逐家实机验证 |
| 仅连接已运行设备 | 不启动模拟器；空的 ADB 路径和地址沿用当前界面设备 |
| 模拟器程序路径 | MuMu 填 `mumu-cli.exe`，留空查找默认安装位置或 ADB 同目录；自定义模式必须填写 |
| 模拟器实例号 | MuMu 多开器中的编号，如 `0`。与游戏分身的用户 ID 无关 |
| 启动参数 | 自定义模式使用 JSON 字符串数组，如 `["--index", "0"]`，直接传给 EXE，不经过 shell |
| ADB 程序 | 如 `C:\Program Files\Netease\MuMu\nx_main\adb.exe` |
| 连接地址 | 如 `127.0.0.1:16384`。MuMu 留空时从指定实例实际配置读取，不按编号猜端口 |
| 游戏包名 | 中国服默认 `com.bilibili.star.bili` |
| Android 用户 ID | 默认 `0`，打开原应用；应用分身一般从 `10` 开始，具体以模拟器实际用户 ID 为准 |
| 自动下载 | 默认允许游戏资源下载；关闭时遇到下载确认直接停止 |
| 启动超时 | 模拟器默认 180 秒，允许 10–1800 秒 |
| 游戏超时 | 包含下载，默认 1200 秒，允许 30–7200 秒 |
| 未知页面等待 | 默认 60 秒，允许 5–300 秒，给动画和加载留出时间 |

明确填写的连接地址必须与 MuMu 实例一致。不会自动选另一台在线模拟器，不会重启或杀死共享 ADB 服务。停止等待不会关闭已经启动的模拟器。

MuMu 默认安装时，程序路径、ADB 路径和连接地址通常都可以留空。三个程序路径框均提供“选择…”按钮；MuMu 模式选择 `mumu-cli.exe`，自定义模式选择模拟器启动 EXE，ADB 选择模拟器附带的 ADB 程序。地址填写 `127.0.0.1:端口` 或设备列表中的完整序列号，例如 `emulator-5554`。输入项采用上下排列，说明在输入框下方自动换行。

上方控制器类型必须是安卓 ADB。MuMu／自定义模式以本任务的设备设置为准，连接后同步上方设备选择，后续任务共用该连接；“仅连接已运行设备”模式的空路径、空地址沿用上方当前设备。显式指定但未出现在自动扫描列表里的设备，也会加入设备列表并选中；程序切换选择时抑制自动重连，避免连接完成后被再次重建控制器。

## 启动流程

界面在控制器连接前调用 `agent/wakeup_host.py`，解析本任务最终选项，查询模拟器状态、必要时启动，等待 Android `sys.boot_completed=1`，再连接返回的确切 ADB 地址。MFA 的选项参数是按顺序叠加的 JSON 数组，连接前按同样顺序合并。

Agent 的 `StartWakeup` 校验用户和安装包，通过对应用户的 launcher activity 启动应用，并检查前台 Activity 的用户 ID 与包名。已在前台时保留当前页面，不强制停止游戏。MuMu 冷启动后的分身用户可能未运行，需先 `am start-user`，再启动游戏；只看 `am start` 返回成功不足以确认分身已打开。

登录时，同一 Android 用户的系统权限组件可能短暂接管前台。遇到该组件或暂时读不到前台时，任务会暂停点击并等待最多 3 秒；只有确认原用户的游戏恢复前台后，才重新截图识别并继续。持续停留的权限页面需要手动处理；切到其他应用或其他用户仍立即停止。等待、恢复和超时信息写入 `trace.jsonl`。

游戏部分每轮截图后重新判断：资源下载、标题页、下一步、关闭、通知、加载、主页。活动推进不绑定活动名称，使用唯一可见按钮；中英文推进提示按语义匹配，包括 `TAP TO NEXT`、`TOUCH ... CONTINUE` 等，不要求生日或活动标题。通知确认仍复用已有弹窗范围与交易排除检查。背景主页按钮即使模板匹配，也必须保有正常亮度，且连续三次观察到清晰主页才成功。

识别到全屏“新成员登场”标题后，进入专用动画处理阶段，每轮重新截图并检查页面，再点击左侧边缘（1280×720 坐标系的 48,360）跳过，不再等待画面稳定 3 秒。两次点击至少间隔 1 秒，实际间隔还包括截图、识别和输入等待；同一画面最多 3 次，整个阶段最多 40 次。最后一次点击后额外观察最多 3 秒确认延迟切页，不能继续追加点击。弹窗、明确按钮或清晰主页出现时结束快速点击，交回对应流程；加载、纯色过渡帧、登录／选择／消费提示和边缘控件不点击。点击后的成功仍由新截图确认，最终必须连续三帧确认主页。

新成员阶段使用固定 180 秒期限，不与整串展示共用普通未知页面的 60 秒等待；重复标题、画面变化和点击都不延长期限，整次唤醒只开启一次，并仍受游戏总超时和 100 步上限约束。超时或点击次数耗尽会保存现场停止，不转为普通保底继续点击。日志与报告分别记录“已识别新成员登场”和“跳过新成员展示”，补点记录同一画面仍未推进的原因。

其他全屏启动页未识别到按钮时，先等待画面稳定约 3 秒，再尝试点击左侧边缘，不依赖 OCR 必须读到文字。保底点击至少间隔 3 秒，同一画面最多 3 次，整次唤醒最多 12 次；点击后重新截图，点击本身不算任务成功。未识别到标题的新成员宣传画仍可使用此保底，宣传画中的“招募”“购买”“付费”等词不阻止边缘点击。弹窗、已识别的加载页、纯色过渡帧，以及包含登录验证、下载更新或选择提示的页面不使用保底点击；边缘已有识别文字时也不点击。未知页面等待超时仍保存现场并停止，保底点击不延长该超时。日志与报告将保底点击单独记为“启动页保底点击”。

会话中途离开游戏或切到其他用户时停止。登录验证、维护、实名认证和需要前往商店安装的客户端更新目前交给用户处理；本次实测覆盖的是游戏内资源下载，不能等同于客户端 APK 安装更新。

## 记录与持续适配

开场剧情复用演出／故事任务的通用剧情菜单、跳过模板，同时要求同一位置的 OCR 按钮文字匹配。按“菜单 → 跳过 → 确认”推进，每次操作后重新识别；弹窗、加载和需手动处理的页面不点击背景剧情控件。不依赖角色名、活动标题或对白内容。相同操作连续五次未改变页面即停止，整次唤醒仍受总超时和 100 步限制，最后必须连续三帧确认清晰主页才算成功。除已确认的新成员展示专用阶段外，其他未知页面的 60 秒默认等待与保底点击上限保持不变。

每次游戏唤醒在 `debug/wakeup/<时间>-<唯一后缀>/` 下保存：

- `frame-*.png`：发生明显变化的观察帧，包括过渡动画、下载和通知内部截图。
- `<序号>-<动作>.png`：点击前页面；`home.png` 为成功主页，`error.png` 为失败现场。
- `trace.jsonl`：经过秒数、截图文件、OCR 文本／范围／置信度、点击坐标和页面判断。
- `report.json`：设备、Android 用户、规则版本、步骤与最终结果。

主机启动和连接错误记录在界面日志中。日志和截图可能包含账号页面信息，分享前检查。

通用文字规则集中在 `agent/data/wakeup_rules.json`。新增规则优先匹配按钮语义与可见范围；不要以某一期活动名称写死整个流程，不要让公告底下的“招募”“跳转”触发操作。每条新规则用真实保存帧补充测试，并验证未知弹窗和交易确认不被误点。

2026-10-22 的一次性样本保存在 `tests/fixtures/wakeup/`：约 15 MB 数据下载、首次登录金币、黄金周徽章、两页星石奖励、SPECIAL 追加通知、商品宣传关闭页。`provenance.json` 标明采集来源；`startup-trace.jsonl` 保留该轮原始观察记录。采样期间补充了宣传页关闭规则后续跑；这些样本不代表所有活动都已覆盖。

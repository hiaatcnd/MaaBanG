# Bestdori 档案同步

MaaBanG 侧栏的“工具 → Bestdori 档案”是独立原生页面，不属于日常任务队列，不使用外部浏览器。未连接模拟器时也能管理档案；仅点击“读取游戏”才占用当前实例的设备。

## 使用流程

1. 打开 MaaBanG 侧栏的“工具”。
2. 在“底稿与范围”选择底稿：粘贴或打开 Bestdori 导出的 JSON／文本资料；在“Bestdori 账号”登录后读取并选择云端档案；或者使用空白中国服档案。
3. 选择乐队、成员、星级和种类，并设置冲突处理方式。种类支持 Powerful、Cool、Pure、Happy 多选，默认全部选中。成员选择按游戏顺序排列，每队左侧“选择 5 人”，右侧为五位成员；横杠表示部分成员，点击横杠会全选该队。在“读取与核对”点击“读取游戏”，使用主页当前选择的设备。游戏停在主页、乐队菜单或成员列表。扫描先在游戏内设置成员、星级和种类筛选，并核对全部乐队的选中状态，清除之前的未读故事和仅动画卡牌等限制。
4. 检查读取记录。身份未确认的记录默认不采用，可在下方搜索卡名并“确认当前记录身份”，无需手填数字 ID。已有卡缺失字段保留底稿，新卡信息不完整则跳过并提示。
5. 确认保存后的档案名称，点击“查看合并结果”，确认新增和更新记录。修改范围、数值或策略后须重新预览。
6. 导出／复制资料后，在 [Bestdori 用户档案管理器](https://bestdori.com/profile/manager) 中使用“导入资料”；也可登录后“新增云端档案”，或以云端档案为底稿后点击“替换当前云端底稿”。
7. 扫描期间可“停止读取”，保留已读记录。切换侧栏页面不会关闭档案工具；账号可随时退出登录，退出 MaaBanG 时结束会话。

扫描完成后留在成员列表。取消或遇到未知页面时保留已读取记录，并标明扫描未全部完成；不会把部分扫描当作完整账号快照。扫描不进行练习、特训、故事解锁或材料消费。扫描通过当前实例的执行锁与普通任务互斥，不运行任务前后脚本或任务结束操作。

卡牌按明确 ID 从 Bestdori 获取 180×180 官方小图、技能名称和完整效果，按右侧实际技能等级计算持续时间和回复量；修改技能等级后立即更新效果，无需重新下载。技能全文换行、行高随内容调整，单图和双图共用固定图片区域，右侧文字对齐。特训前后小图并排展示。一／二星及只有一种卡面的动画卡只显示可用的一张；Kira Fes 动画卡即使没有额外特训等级，也使用 `after_training` 小图。图片响应必须能解码且尺寸匹配；中国服资源不可用时尝试同一卡的其他服公开资源，损坏缓存自动重取，可手动重试。资料请求不携带账号凭据，公开资料缓存在 `public-cache/`。

翻页使用列表空白边缘，等待稳定后根据网格位移与每行多个相邻卡面确认唯一对应关系，只跳过已经访问过的重叠位置，不凭单张相似头像认定同一卡牌。返回列表允许轻微位置偏移与个别动画卡面变化，并更新下一张的点击坐标；只有仍为同一列表时才重试未响应的点击。滑动无进展、连续重复页面、卡片行不完整或不能确认到底时，保留部分结果并停止。星光直接读取详情卡面右侧菱形标记，不打开星光练习；进入详情后也不重复点击默认数值页签。

读取原值、核对值及采用勾选分别缓存；扫描完成后先在服务端固定原值和扫描会话，再交给界面调整。旧版核对缓存中的原值只从最新已完成且范围、完整卡牌集合匹配、扫描早于缓存的原始扫描中恢复；保留已修改的目标值和采用状态，保存前备份旧缓存。新版缓存中主动清空的值不自动补回。重新打开会显示缓存时间和上次读取是否完整，重新扫描仍读取实际游戏状态。

“查看合并结果”展示底稿和读取值合并后的变更，这一步不会上传。变化字段显示“原值 → 新值”，绿色表示提升，橙色表示降低，未变化值为灰色；新增卡牌单独标记。

“读取与核对”的每张卡同表展示底稿、读取原值和合并目标三行数值。点击目标行的紧凑输入框即可修改，回车或移出输入框确认，Esc 取消；底稿和原值始终可见，非法数值不采用。目标随覆盖／取最大值策略计算，技能效果随目标技能等级更新；修改数值不会改变读取原值。“只看有变化”仅保留范围内、采用且能合并的新增／变化卡牌，按目标与底稿比较，合并后不变的记录不显示。关闭开关恢复全部记录。保存和导出仍需先生成当前设置的合并结果。

## 合并规则

范围由选中的成员、星级及种类共同决定，各项至少选择一项。种类选择随核对记录缓存，旧版缓存未记录种类时按全部种类恢复；更新卡牌目录保留当前选择。按 Bestdori 卡牌 ID 匹配，底稿中不在范围内、没有扫描到的卡牌都保留，不自动删除。当前仅允许更新中国服底稿，防止不同服务器的卡牌状态混用。

| 内容 | 处理方式 |
| --- | --- |
| 指定数值提升 | 等级、技能、星光可独立指定；取读取原值、当前核对值与目标值的最大值，目标值按该卡上限限制 |
| 等级、技能等级、星光等级 | 覆盖：使用确认的游戏值；最大值：每项分别取底稿和游戏值的最大值 |
| 特训状态 | 从等级上限推导，随相同策略处理；等级与特训上限不一致时跳过并提示 |
| 未确认字段 | 已有卡保留原值；新卡缺少等级、技能、星光或特训之一时不新增 |
| 故事、卡面、排除设置 | 已有卡原样保留；新卡故事设为未读、卡面跟随特训、不排除 |
| 区域道具、角色潜能 | 原样保留底稿；本版本不扫描这两类数据 |
| 重复 ID | 底稿重复 ID 保留并提示；采用的扫描记录存在重复 ID 时要求先处理 |

“星光等级”是游戏卡牌的 Master Rank，范围 0–4；它与底稿道具中的角色潜能是不同字段。页面技能等级显示 1–5，Bestdori 资料中以 0–4 保存。

在“读取与核对”中勾选项目并指定目标值，点击“提升勾选卡牌”，只处理采用栏勾选的卡牌；已有较高值不会下降。提升等级超过特训前上限时，档案中的特训状态同步设为已特训。读取前设置目标时，扫描仍读取原值，完成后对确认采用的卡牌应用目标。缺失且未经核对的字段保持为空并提示，不用目标值冒充实际读取值。

“还原勾选卡牌”恢复读取时的等级、技能、星光及特训值，清除调整状态；未读取的字段恢复为空。原值与核对后的值分别缓存，重启后仍可还原。旧缓存曾跳过读取的字段没有原值，需要重新读取。以上操作仅修改档案，不执行游戏培养。

## 账号与云端

登录直接使用 Bestdori 的 HTTPS 账号接口，密码和 Bestdori 登录 Cookie 只在进程内使用，不写入配置或日志。选择云端底稿不会修改它，同时绑定替换目标并带入原名称。合并结果可直接替换该底稿，或改名新增；保存区明确显示目标名称、账号和位置。导入文件、切换空白底稿或重新登录会清除替换目标。

Bestdori 当前保存接口写入的是完整档案集合。程序先读取并保存原集合备份，再次读取确认未变化。新增时提交“原集合 + 新档案”；替换时核对底稿所属账号、位置和内容指纹，只替换对应位置，最后回读核验。底稿已变化则要求重新读取和合并。原集合中的其他档案保持其原始内容，不重新解码编码。上传超时先回读，不自动重复提交或回滚。替换尝试结束后须重新读取底稿才能再次替换，避免不确定结果被重复提交。

接口没有原子版本检查，仍无法排除检查后另一个设备同时保存的竞争，请避免同时在其他设备保存云端资料。回读不一致或无法确认时会明确报错，保留备份和导出文件。

原生页面通过私有子进程管道获得一次性令牌，调用只监听 `127.0.0.1` 随机端口的本机服务。HTTP 接口校验令牌和来源，不提供网页。令牌不进入任务参数或日志；扫描使用独立、一次性的作业 ID 交接，不携带账号凭据。父进程管道关闭时，服务取消自己的扫描，等待已开始的云端保存与回读完成后清除账号会话并退出。

## 文件位置

所有资料写入当前 MaaBanG 用户数据目录下的 `bestdori/`，遵循 `MAABANG_DATA_DIR`，开发配置和正式配置仍分别保存：

- `snapshots/<本次会话>/`：底稿、合并结果、扫描报告和识别截图。
- `exports/`：完整、可供 Bestdori 导入的 JSON。
- `backups/`：每次云端写入前的完整集合备份。
- `catalog.json`：点击“更新卡牌目录”后保存的公共目录缓存。
- `public-cache/`：逐卡公共资料、技能目录和经过校验的小图。
- `last-scan.json`：最近读取／核对记录、采用状态、范围和缓存时间；不含账号凭据。
- `jobs/<一次性 ID>/`：扫描范围、目录、取消标记、进度、扫描报告和识别截图，不含账号凭据。

底稿支持未压缩 JSON 和 Bestdori 的压缩版本 1／2。默认导出未压缩 JSON，云端保存使用版本 2。未压缩资料的扩展字段保留；含未知扩展字段时禁止有损压缩上传，仍可导出文件。无法完整识别的新版压缩资料会拒绝导入。

## 开发与验证

主要实现位于 `agent/bestdori*.py`，原生页面为 `tools/MaaBanGBestdori.cs`，设备占用和执行桥接为 `tools/MaaBanGBestdoriRunner.cs`，离线目录为 `agent/data/bestdori.json`。`tools/patches/mfaa-bestdori-tool.patch` 添加侧栏入口。`build_ui.py` 和 `install.py` 将页面与补丁纳入 UI 编译和发布源码包。`BestdoriProfiles` 仍是内部扫描动作，保留在 Agent 注册与资源节点中，不再列入用户任务列表。

开发编译：

```powershell
uv run --project agent python tools/build_ui.py
```

通过独立开发配置打开编译包后，从侧栏进入工具页。开发者也可用 `tools/run_bestdori.py --adb <路径> --address <地址> --scan-limit 3 --stars 5` 仅浏览三张五星卡，报告一定标为未完整扫描。

回归测试：

```powershell
uv run --project agent python -m unittest discover -s tests -p "test_bestdori*.py" -v
```

测试覆盖压缩格式、范围交集、覆盖／最大值、三项拉满的八种组合与跳过读取、未知字段保留、部分扫描、云端竞争与超时、来源校验、一次性扫描交接与父进程退出，覆盖翻页重叠、末行触边、无进展与重复页面保护，并用真实截图离线识别一星／四星／五星卡、彩色星星及星光等级 0 和 4。截图顶部账号数值已遮蔽。

`tests/bestdori_ui/` 使用 [Avalonia Headless](https://v11.docs.avaloniaui.net/docs/concepts/headless/) 运行真实原生控件和本机服务，验证筛选、拉满、覆盖／最大值、旧预览失效和导出格式，并生成不同窗口大小的截图；不连接游戏。先构建 UI，再运行 `dotnet run --project tests/bestdori_ui/BestdoriUi.csproj -c Release -- <仓库路径> <Python路径>`。第三个可选参数是账号文件，仅在用户明确授权真实账号联调时使用；该模式会创建一个明确命名的云端测试档案。

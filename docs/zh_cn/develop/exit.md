# 退出任务

在任务列表添加并勾选“退出”，选择一种退出范围。默认不勾选；执行时排在普通任务后，每个队列最多一个。

| 范围 | 行为 |
| --- | --- |
| 关闭应用 | 用 ADB 结束指定包名、Android 用户下的应用，再核对该用户的停止状态。原应用默认用户 0，分身一般从 10 开始。 |
| 关闭模拟器实例 | 使用 MuMu 官方 CLI 关闭指定实例，轮询确认实例已停止；其他实例保留。 |
| 关闭模拟器程序（全部实例） | 关闭此 MuMu 安装下的所有运行实例，确认停止后调用 `main close` 退出主程序。不会强杀进程或关闭全局 ADB 服务。 |

“沿用本轮唤醒 / 当前设备”默认继承本轮勾选的开始唤醒任务中的设备、包名和 Android 用户，并使用唤醒后实际连接的 ADB 地址。没有唤醒时使用上方当前安卓设备，应用默认包名 `com.bilibili.star.bili`、用户 0；关闭实例时通过当前地址匹配 MuMu，无法唯一确定时失败，不猜测实例 0。已经停止的 MuMu 可能不再返回 ADB 地址，这时可用“指定退出目标”填写实例号。

“指定退出目标”独立填写 MuMu 路径、实例号、ADB 和应用用户。MuMu 实例号从 0 开始，路径和地址可留空自动读取，路径支持文件选择。仅通过 ADB 关闭应用支持其他模拟器；实例/程序关闭目前适配新版 MuMu 的 `mumu-cli.exe`。

单独勾选退出时跳过队列的启动脚本、设备初始化、截图测速和 Agent 创建，不会先启动模拟器。目标 MuMu 实例已经关闭视为成功。手动停止或队列提前中断不会强行执行退出；前面的任务按“错误后继续”策略继续时，退出仍会正常执行。

## 记录与验证

每次执行在数据目录 `debug/exit/<时间>-<标识>/` 写入 `report.json` 和 `trace.jsonl`，包括目标、实际实例、命令、返回状态及错误。正在执行时取消会停止宿主等待进程，已发出的关闭命令无法撤销；中断记录可能保留 running 状态。关闭超时不会强杀进程。

2026-10-22 本机实际验证记录：`debug/exit-live/20261022-014751/`。

- 关闭实例 0 中 Android 用户 10 的游戏分身，用户 0 的游戏保持运行。
- 关闭实例 1，实例 0 的进程号与原应用状态保持不变。
- 再次关闭实例 1 成功，没有重新启动模拟器。
- 保存了前后截图、实例清单、应用状态和每一步命令。

整程序退出通过命令模拟测试验证关闭顺序和失败处理，使用已安装 MuMu CLI 提供的官方退出命令；本轮未对仍运行游戏的全部实例执行整程序关闭。桌面代码已编译，目标继承及 360/760 像素输入布局已通过无窗口验证；原生桌面点击流程未在本轮完成自动化验证。

实现：`agent/exit_host.py` 执行退出；`tools/MaaBanGExit.cs` 解析目标并接入队列；`tools/patches/mfaa-zz-exit.patch` 提供桌面调度；`tools/update_exit_interface.py` 生成界面和 pipeline。旧版桌面或其他客户端直接调用 ExitGame 时，Agent 明确提示需要升级，避免报告虚假的退出成功。
